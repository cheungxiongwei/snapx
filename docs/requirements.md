# snapx 需求

snapx 是一个面向自动化场景的 Windows 命令行截图工具。它让开发者、测试流水线与 AI 代理在不弹出任何交互界面的前提下，截取指定应用窗口或主显示器全屏，并把结果输出为图像。本文件从产品视角描述 snapx 要解决的问题、提供的能力与验收标准；命令行契约见 [`cli-spec.md`](cli-spec.md)。

需求：

- 用户在无人值守、无法进行人工点击的环境中完成截图。
- 用户以进程 ID 精确指定要截取的目标应用，避免同名多进程带来的歧义。
- 用户可截取单个应用窗口，也可截取主显示器整屏。
- 用户可把截图落盘、直接写入管道，或复制到剪贴板，以适配不同的后续处理方式。
- 截取结果可被 AI 代理消费。
- 当目标不存在或截取失败时，用户能得到明确、可判定的失败信号。

### 能力

snapx 为用户提供三项能力：

- **查找目标**：列出当前可截图的窗口及其进程 ID、进程名与窗口标题，帮助用户确定要截取的对象。
- **截取窗口**：按进程 ID 截取一个具体应用的窗口。
- **截取全屏**：截取主显示器的完整画面。

截取结果可输出为 PNG、JPEG 或 BMP。用户可指定输出尺寸倍数，并可为 JPEG 指定质量。

### 行为

- 同一进程 ID 对应唯一确定的窗口，结果稳定可复现。
- 目标窗口处于最小化状态时仍可截取；截取过程不改变窗口原有状态。
- 用户不指定文件名时，产品依据进程名与时间自动命名，避免连续截图互相覆盖。
- 用户可将图像写入标准输出，使其能直接接入后续命令的管道。
- 用户可要求把图像复制到剪贴板而不产生文件；此时图像对主流图像编辑、办公与浏览应用可直接粘贴使用。
- 成功时给出包含图像尺寸、格式与保存位置的明确回执。
- 失败时给出可读的原因，并以可判定的方式与「参数用法错误」相互区分。

### 约束

- 操作必须是完全非交互的：单次调用完成一次截取后退出，不要求用户确认，不弹出系统选择界面。
- 目标由用户显式指定的标识（进程 ID 或主显示器）确定，产品不代为猜测。
- 支持的图像格式限于 PNG、JPEG、BMP；其他格式的需求通过外部工具经管道转换实现。
- 输出目标为文件时，同名文件会被覆盖。
- 仅支持 Windows 桌面环境；不支持该能力的环境在截取时明确报错。
- 部分受保护内容（如数字版权保护画面）可能无法截取，此时按失败处理。
- 截取期间在目标窗口周围出现的系统提示边框属于操作系统固有行为，产品无法关闭。

### 验证

- 用「查找目标」取得一个正在运行的应用的进程 ID，再以该 ID 截取，确认得到尺寸正确的图像，且回执中的格式与位置与实际一致。
- 分别以 PNG、JPEG、BMP 输出，确认生成的文件可被对应格式正常打开。
- 以不存在的进程 ID 截取，确认收到明确失败。
- 截取最小化窗口，确认成功且窗口在截取后仍保持最小化。
- 执行全屏截取，确认得到主显示器的完整画面。
- 将图像写入标准输出并重定向，确认得到可解码的图像，且提示信息不混入图像数据。
- 使用剪贴板输出后粘贴到常见应用，确认图像正常。
- 以错误的参数用法调用，确认收到与运行期失败相区分的用法错误提示。
