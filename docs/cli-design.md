# CLI 界面设计风格

一份自包含的命令行界面设计风格指南，供为本项目及后续工具设计 CLI 时复用。核心目标是**职责清晰、平铺易扫读、新手无需查阅即可上手**。文中示例均为通用占位，不依赖任何具体工具。

## 1. 总原则

- **命令代表操作域**：一个命令是一个用户可以独立描述、独立理解、独立获得帮助的「动作或操作域」。命令之间职责互斥，不重叠。
- **选项只是域内参数**：选项描述某个命令的行为与参数，只在所属命令下有效，不在命令之间复用。
- **职责归一**：当一个命令是只读查询、另一个命令产生副作用时，它们必须处于不同命令域，绝不把两类选项压进同一层命名空间。
- **平铺优先**：命令与选项排成平面列表，不按 `Target` / `Output` / `Other` 这类主题做嵌套分组。
- **一个选项一行**：描述压成单行，不折行、不续行。宁可精简措辞，也不换行。
- **用法自明**：`usage` 就写清哪条命令配哪些参数，读者不必猜测 `options` 指代什么。

## 2. 何时用命令，何时不用

命令（子命令）不是必须的。按操作域数量与职责边界判断：

- **只有一个动作、没有查询类旁支**：不要引入命令。直接一层选项即可，如 `tool <file>`、`tool -o out`。
- **存在两个以上职责不同的操作域**：使用命令隔离。典型如「查询/列举」与「执行/改动」应各占一个命令。
- **命令很轻但选项很多**：命令依然合适，因为它隔离了选项命名空间，避免不相干的选项互相干扰。

判断口诀：**如果两个功能同时出现会让「该忽略还是该报错」成为一个需要讨论的问题，就说明它们该分到不同命令。**

## 3. 层级与命名

- 命令用动词原形，短而具体，如 `scan`、`capture`、`list`、`run`。
- 命令必须显式给出，不省略、不猜测。选项出现在命令之前即为错误。
- 若确需两级（命令 + 子命令），仅在操作域内部确有稳定分类时使用；否则保持单级。
- 长选项用完整单词，短选项取首字母；同一长选项可配一个短别名。
- 一个选项只属于一个命令域。跨命令选项名相同也视为不同选项，各自独立校验。
- 不保留与当前模型冲突的历史别名；迁移成本高时，可在文档中给出替换说明，而非让旧别名长期寄生。

## 4. 整体帮助结构

顶层帮助自上而下分三块，块间空一行：

1. **单行简介**：`<name> - <一句话用途>`。
2. **usage**：每种调用形态一行，覆盖全部命令。
3. **命令列表**：每个命令一行简要描述，末尾提示如何获取命令级帮助。

命令级帮助（`<name> <command> --help`）：

1. **单行简介**：`<name> <command> - <一句话用途>`。
2. **usage**：该命令的完整调用形态。
3. **该命令的选项列表**：只列属于本命令的选项，不列全局或他命令选项。

`--help` 在任意位置都有效：顶层显示总帮助，命令上下文显示该命令帮助；命令上下文中的 `--help` 覆盖该命令的其余校验。

## 5. 排版规则

- 名称与描述之间对齐，用空格补齐到统一描述列。
- 层级只允许**两格缩进**一级，禁止更深嵌套。
- 描述列内不放段落、不放项目符号；补充信息用括号内联，如 `(.png .jpg .jpeg .bmp)`。
- 不设置 `Exit codes`、`Notes` 一类独立段落；退出码、运行时长提示等放进规范文档或选项描述中。

## 6. 选项写法

- 选项名格式：短选项与长选项同列写作 `-o, --output <p>`；仅长选项写作 `--pid <id>`。
- 占位符统一用尖括号：`<id>`、`<path>`、`<n>`。描述中提及占位符时保持一致。
- 必填项在描述末尾标注 `(required)`；可选项一律给出默认值与取值范围。
- 布尔开关描述结尾不加句号，保持与其他行一致。
- 取值范围用区间记法 `(0.0, 5.0]`、`1-100`；默认值写成 `default 1.0`。

## 7. 文案

- 简介、usage、描述全部使用同一语言与语域。
- 描述用祈使/陈述短句，不加主语，不加句末句号。
- 示例行可执行、可复制，值尽量贴近真实。
- 有输出可展示的命令（如列举类），在示例中直接贴出模拟输出。
- 错误消息统一前缀 `error: `，文本稳定、可被脚本依赖；参数错误随后打印 usage 并以固定退出码结束。

## 8. 退出码

- 语义固定，全网统一：`0` 成功；`1` 运行期失败；`2` 用法/参数错误。
- 参数错误时把 `error: <message>` 与 usage 写到 stderr，再以约定退出码结束。
- 用法错误提示应直接给出可复制的正确写法，而不只是报错。

## 9. 范本

顶层帮助：

```
tool - do something useful with a resource

usage:
  tool query [--help]
  tool run <id> [-o <path>] [-s <n>]

commands:
  query     read and list available items
  run       act on one item by id

run 'tool <command> --help' for details
```

命令级帮助：

```
tool run - act on one item by id

usage:
  tool run <id> [-o <path>] [-s <n>]

options:
  <id>          item id to act on (required)
  -o, --output <p>  output path, '-' for stdout
  -s, --scale <n>   size multiplier, default 1.0, range (0.0, 5.0]
```

## 10. 检查清单

设计或评审一个 CLI 前，逐条核对：

- [ ] 每个命令都是一个可独立描述、独立理解、独立获取帮助的操作域。
- [ ] 选项只在其所属命令下有效，命令之间命名空间隔离。
- [ ] 查询类与副作用类功能不在同一命令中，无需讨论「忽略还是报错」。
- [ ] 每个命令都有 `--help`；顶层帮助给出命令列表与获取命令级帮助的提示。
- [ ] 帮助只有简介 / usage / 列表三块，无主题嵌套分组。
- [ ] 每个选项一行，描述未折行。
- [ ] 必填有 `(required)`，可选有默认值与范围。
- [ ] 退出码语义固定，错误消息稳定且带 `error: ` 前缀。
- [ ] 不存在与当前模型冲突的历史别名寄生。
